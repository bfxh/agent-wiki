关键设计点

感知与决策解耦

感知层只管「事实是什么」，决策层只管「事实 → 意图」。
中间用 Sensor 结构体传递。

好处：不开数据包时（dry 通道），决策层照跑，只是输入全是未知 → 全弃权。
离线和实机跑的是同一套代码路径。

战法不改行为，只改权重

strategy.rs 里每条战法就是一组权重调整。
所以「底层战术」和「上层战法」能在同一张 sim 表里同时看到。

注入是最后一层

act/mod.rs 定义 CommandSink trait，高层只说「做什么」，
具体怎么送到游戏由实现决定：

  • win32.rs —— SendInput 真注入
  • dry.rs —— 只记录
  • squad.rs 的 ChatSink —— 走游戏命令框

零第三方依赖

只用 std + 手写 FFI。需要 Win32 / 注册表 / 时间戳时手写。

这是硬约束，不是洁癖：
项目要能塞进整合包作者的机器、能长期维护、不能因为某个 crate 停止维护而烂掉。

  perceive/mod.rs                  datapacks/trit_bridge/
  ├─ PROTOCOL_FIELDS ──────────►   │  tellraw 打 <TRIT hp=...>
  │      │                          │
  │      │  trit-agent protocol    │  聊天框
  │      ▼                          ▼
  └─ parse_patch  ◄────────────  logs/latest.log

Rust 侧有测试锁住「名单和解析器分支逐字一致」。
