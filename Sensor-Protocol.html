传感器协议

跨仓库的唯一集成点

trit_bridge 用 tellraw 把感知量写进聊天，Rust 侧再按 k=v 解析回来。

这是两个仓库之间唯一的集成点，而且中间没有任何握手。

静默失败

> 字段拼错一个字母，两边都不报错，只是这个量永远等于「没感知」。

不报错、不崩溃、不写日志——AI 就是「看不见」了。
所以这条线必须被交叉校验。

两条通道

通道前缀频率字段
慢<TRIT 1 秒（20 tick）hp food x y z h d c w wd o od t p
快<TRITF 100ms（2 tick）wal b1 bd s p

格式：

<TRIT  hp=200 food=17 x=123 y=-601 z=88 h=3 d=6 c=0 w=6 wd=-1 o=4 od=1 t=15200 p=150>
<TRITF wal=5 b1=2 bd=3 s=1 p=280>

wal 是 8 位掩码（八个方向有没有墙），b1/bd 是方块类别码，
s 是台阶，p 是俯仰角。

完整字段表（18 个）

字段含义通道
hp血量（×10）慢
food饥饿值慢
x y z坐标（×10）慢
h敌人数慢
d最近敌人距离档（0~5）慢
c危险方块档（岩浆等）慢
w原木距离档慢
wd原木方向慢
o矿石距离档慢
od矿石方向慢
t游戏内时间慢
p俯仰角（×10）慢+快
wal墙体掩码（8 位）快
b1准星方块类别快
bd脚下方块类别快
s台阶标志快

契约：名单由 Rust 侧导出

字段名单不在 MC 仓库手写。手写名单会跟代码脱节，
改名时两边一起过时，检查反而变成「两边都错所以通过」。

代码是唯一事实来源：名单在 Rust 的 perceive::PROTOCOL_FIELDS 里。

trit-agent protocol          # 一行一个字段
trit-agent protocol --json   # 脚本读这个
# ["hp","food","x","y","z","h","d","c","w","wd","o","od","t","p","wal","b1","bd","s"]

守门测试

Rust 侧有一个测试盯着「名单和 parse_patch 的 match 分支逐字对应」：

#[test]
fn protocol_fields_match_parser_branches() {
    // 从源码抠出 match 分支，和 PROTOCOL_FIELDS 逐项比
}

改了解析器忘了改名单（或反过来），这里立刻红。

> 这个测试当场抓到我自己的 bug：提取逻辑被测试文件里同名的字符串干扰，
> 抠出来只有 1 个分支——测试自己写错了，测试就抓不到测试自己。

交叉校验

MC 侧的打包器每次都拿这份名单校验数据包实际输出的字段。查两件事：

  1. text 里声明的协议字段名（<TRIT hp= 的 hp）必须在 Rust 白名单里；
  2. k= 标签的个数必须等于 score 片段的个数（多一个标签＝写了标签没取值）。

不查「标签和取值是不是同一个量」：
score 片段取的是记分板假人名（px/hst/dst），名字随便起，
跟协议字段名无关，比对没有意义——一开始写了这条，结果 24 条全是假阳性。

拿不到名单怎么办

校验器会显式报告「跳过」，不假装通过：

  • 首选：调 trit-agent protocol --json
  • 降级：读旁边 Rust 仓库的源码（../trit-agent/src/perceive/mod.rs）
  • 两条都拿不到：报告跳过

合并两帧

Rust 侧把两条通道合并到同一份状态：每条帧只带自己有的字段，
缺的字段保持原值（SensorPatch → Sensor::apply）。

不这么做的话，快帧每 100ms 就会把「有几个怪」清成 0——
AI 会以为世界永远安全。

关掉传感器

/function trit_bridge:off      # 关掉整个传感器
/function trit_bridge:on       # 打开
/function trit_bridge:fast_on  # 只开快通道

快通道默认关，由 AI 在采集/挖矿时按需打开，收手后延迟 2.5 秒关。
