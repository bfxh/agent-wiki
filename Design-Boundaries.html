能力边界

知道做不到什么比知道能做什么更有用

> 这一页是诚实的部分。知道它做不到什么，比知道它能做什么更有用。

它能做的

  • 稳定的战斗节奏（挥击 / 跳劈 / 换边）
  • 卡血撤退、低血站桩回血
  • 死亡后点重生
  • 巡逻扫视
  • 砍树、挖矿（带完整门控）
  • 随时接管与交还（F8）
  • 一个大脑指挥傀儡和狼

它做不到的

没有视觉，也不知道敌人方位

数据包只给「最近敌人多远」，不给方向。

所以视角不会朝敌人转（Yaw 只在待命时才扫视），也不会主动走位绕后。

这是最本质的限制——它是个「近身反应」系统，不是「战场感知」系统。

不开数据包时只有「日志里写了什么」

也就是死亡消息和你打的字。

这时候 assume_threat = false（默认）会让它站着不动——这是刻意的，
猜错方向的代价比不动大。

反应延迟 ≥ 1 个传感器周期

慢通道 1 秒（敌人/资源），动手期间快通道 100ms（瞄准/碰撞）。

这是「日志 → 状态机」这条链的物理下限，高频节拍抹不掉它。
想要更低只能写 mod 直接读内存。

不认路、不会寻路

没有 baritone 那种路径规划。

采集是「我看见了、直线走过去」，前方被挡就换目标，不会绕。

不换工具

木镐挖钻石矿会掉、会挖很久。

gather_max_chop_ms（25 秒）是唯一兜底——挖不动就放弃并冷却。
外部注入没法可靠地换槽位（数字键能切快捷栏，但 AI 读不到「第几格是什么」，
开环切等于赌博）。

「看见墙」是近似的

八个方向各测 1 格、靠自己拼的方块标签（16 个原版 tag + 96 个方块）。

漏掉某个方块 = 以为能过去然后撞上，由 stuck 检测兜底，不会崩。

鼠标灵敏度要手调

MC 的「每像素转角」跟灵敏度设置强相关，
默认 look_gain = 1.35 是按灵敏度 0.5 估的。
转太快就调小，转太慢就调大。

手眼要分开看

AI 会抢你的鼠标和键盘。按 F8 关掉才是安全的对话姿势。

验证到哪一步了

已验证

  • 209 个测试：K3 真值表、平衡三进制往返、迟滞不抖、弃权优先、

日志解析与半行/截断/乱序、快慢通道补丁合并、墙体方位映射、采集门控、
挖矿三条地形判据、视线闭环自适应等待、感知延迟实测、快通道开关时机、
协议字段名单与解析器分支逐字一致

  • release 构建 0 警告，cargo clippy --all-targets Error = 0
  • sim --gather / sim --mine / selftest 实跑
  • 数据包 JSON 与 function / 方块标签引用校验
  • 端到端（假 GLFW30 窗口 + 注入 F8）：挂上窗口 → F8 接管 → F8 交还 →

自动回等待态，200Hz 满帧

  • 守护进程自愈：连续强杀 3 次，全部 1 分钟内复活

没验证

  • 原木/矿石射线的实际命中率（多高、多远、树干细的时候漏不漏）
  • rotated ~D 0 在 1.18.2 的取值语义
  • #minecraft:logs / #trit_bridge:ores / #trit_bridge:solid 到底覆盖了哪些方块
  • 快通道每秒 10 行对聊天框的实际观感

（嫌吵就 gather_fast_bridge = false，AI 会自动回落到 1 秒档，只是瞄得慢一点）

> 这几个都只能进游戏才能确认。
> 手上没把握就先用 gather_quota = 1 试一趟，先砍树再试挖矿。

诚实说明

历史上出过两次真实崩溃（见 崩溃排查）。
两次都定位到了字节码级，第一次是我们自己的 bug（待机时改窗口标题），
第二次是整合包自带 mod 的 bug（rrls）。

但守护进程曾经静默死亡这件事，
我没能 100% 证明那次死亡就是 panic——
当时进程已消失、没有崩溃转储，事后无法取证。

排除了崩溃/误杀/进程树连带/切片越界四条路，
剩下唯一符合全部证据的解释是 panic + 无输出。
修复方向对症（panic 现在会落盘、再死会自愈），
但首次死亡的确切触发点仍需实机验证来确认。
